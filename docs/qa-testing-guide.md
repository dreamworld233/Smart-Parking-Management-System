# 测试版验收指南（组员用）

> 2026-09-17 发布测试版。给组员直接扫体验版二维码测，按本指南走关键路径。
> 数据是真实链路：云开发环境 `cloud1-d8gzxlbnq9a5cbf75`，签约车场 4 家（合肥大学等，价格是「示例数据」暂定值）。

## 0. 已知限制（测之前先读，别当 bug 报）

| 项 | 现状 |
|---|---|
| 支付 | **模拟支付**，点「确认支付」即成功，不收真钱 |
| 价格/车位数 | 演示暂定值，界面标注「示例数据，待核实」 |
| 核销码 | 6 位数字，**无二维码**（设计稿的扫码未做，拍板延后） |
| 余位 | 车场端上报后才有值；未上报显示「待上报」，不可预约 |
| 预测柱状图 | 未做（等真实预测数据源） |
| 自动扣费 | 不做。预约时预付（预支停车费 + 服务费 ¥2），出场闸机按实收 |

## 1. 数据准备（车场主先做）

需要 **两个微信号** 分别走车主端 / 车场端；同号切角色也行（我的 → 切换身份）。

1. 车场主号登录 → 选「车场管理」身份 → 「我的」→ 切换身份 → 绑定车场（选一家）
2. 看板 → 「上报余位」→ 填当前空位数（如 50）→ 车场端与车主端余位同步

## 2. 车主端用例

| # | 路径 | 预期 |
|---|---|---|
| C1 | 首页地图 + 面板 | 地图出图钉，面板出卡片（签约在前、未签约标注「仅导航」） |
| C2 | 排序 chips | 距离/余位等排序生效 |
| C3 | 点卡片 → 详情 | 面板切详情，余位/价格/可约显示 |
| C4 | 预约确认 | 选到达时刻 → 车牌 → 试算 → 模拟支付成功 |
| C5 | 我的订单 | 新单在列表，详情有核销码（待入场） |
| C6 | 取消订单 | 免费窗口内可退（全额），余位 +1 |
| C7 | 搜索 | 输目的地出联想，点选后拉周边车场 |

## 3. 车场端用例

| # | 路径 | 预期 |
|---|---|---|
| L1 | 看板 | 今日预约/待核销/当前空余车位 |
| L2 | 余位上报 | 上报后车主端余位同步变化 |
| L3 | 核销-输码 | 输车主核销码 6 位 → 入场成功，留痕 |
| L4 | 核销-按车牌 | 选卡确认该车到场 → 核销 |
| L5 | 核销-拍照识别 | 拍车牌 → OCR 识别 → **识别车牌必须与所选预约一致，不一致被拦** |
| L6 | 改价 | 收费配置改动 → 落 `lot_price_changes` 留痕 |

## 4. 定时任务（可验证项）

| 任务 | 周期 | 验证 |
|---|---|---|
| 超时释放 | 每 5 分钟 | 造一张过到达截止的待入场单 → 自动置已释放 + 余位返还 + 记违约 |
| 余位采样 | 每 15 分钟 | `availability_samples` 集合有采样记录 |
| 每日对账 | 凌晨 3 点 | 余位数被钳回合法区间 [0, 总位] |
