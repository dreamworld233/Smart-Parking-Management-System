### 2.1 计费规则

**预支停车费** = `ceil(预留小时数) × 该车场首小时标准价`

预留小时数 = 到达时刻 − 当前时刻。不足 1 小时按 1 小时计。

| 场景（万象城首小时 ¥6） | 预留 | 预支 | 服务费 | 合计 |
|---|---|---|---|---|
| 10:00 预约 10:40 到达 | 不足 1 小时 → 1 | ¥6 | ¥2 | ¥8 |
| 10:00 预约 11:00 到达 | 1 小时 | ¥6 | ¥2 | ¥8 |
| 10:00 预约 12:00 到达 | 2 小时 | ¥12 | ¥2 | ¥14 |

资金流向：预支停车费由**平台代收**后转付车场；平台收入仅为服务费 ¥2。

出场结算：车场闸机按**实际停放时长**计费，系统不参与后续结算，仅在凭证页展示预支金额供抵扣。

退改：支付后 10 分钟内免费改签；之后改签退预支停车费，服务费不退（对齐 PM BR-03）。

## 5. 关键页面设计

### 5.1 首页

- 地图铺满整屏；当前位置蓝点带光晕
- 悬浮搜索框（白底 + 投影）压在地图上，右侧「地图」切换
- 排序 chips：`综合 / 距离 / 价格 / 空位`，默认「综合」
- 底部可上拖面板：拖拽把手 → 「附近 N 个车场 · 已按综合评分排序」→ 车场卡片列表
- 车场卡片：车场名 / `¥N/时` / 步行距离 / 余位 `x/y` / 综合评分 / 推荐理由标签
- **点卡片与点图钉联动**：选中卡片高亮对应图钉，反之亦然
- 顶部若存在未入场预约，插入「即将到来的预约」横条，一点直达凭证页

### 5.2 搜索页

- 顶部：返回 + 搜索框（支持目的地与车场名关键词）
- 上部地图：结果 pin 分布；推荐结果 pin 用主色高亮并带 `★ 推荐` 前缀
- 排序 chips：`综合推荐 / 距离最近 / 费用最低 / 空位最多`
- 结果卡片，每张两个动作：
  - `导航前往` — 免费，调起第三方导航
  - `预约车位` — 付费，进预约确认

### 5.3 车场详情

- 顶部地图缩略 + 悬浮返回
- 信息卡（上浮压图）：车场名 / 评分 / 地址 / 步行距离；三个统计块 = 实时余位 / 标准收费 / 营业时间
- 未来 2 小时空闲预测柱状图（15 分钟粒度，紧张时段红色）
- 收费规则卡：首小时 / 后续阶梯 / 计费步长 / 日封顶 / 夜间费率
- 可预约额度卡 + 一行说明「直接导航前往不收费；预约锁位需支付预支停车费 + 平台服务费」
- 底部固定双按钮：`导航前往` / `预约车位`

### 5.4 预约确认

- 到达时间 chips，5 档并标注预留时长：`现在 / +30 分 / +1 时 / +1.5 时 / +2 时`
- 提示行：预支停车费按预留时长计算，不足 1 小时按 1 小时
- 预约车牌选择
- 费用明细：预支停车费（按 N 小时计 × 单价）/ 平台服务费 ¥2 / 对照行展示选更长预留时的合计
- 预约规则卡：入场截止（到达 + 15 分钟，超时释放并记违约 1 次）/ 支付后 10 分钟内免费改签，之后改签退预支停车费不退服务费 / 出场由闸机按实际时长计费并抵扣
- 底部固定：合计金额 + `提交预约`

### 5.5 预约凭证

`预约成功` 头图 → 二维码 + 车牌 + 预约单号 → 明细卡（车场/到达时间/入场截止倒计时/已支付）→ 入场方式说明（车牌自动识别，道闸异常时人工核销）→ 费用去向卡（预支停车费转付车场 / 服务费为平台收入）→ 三按钮 `改签` / `取消预约` / `导航前往`

### 5.6 订单中心

四个状态页签：待入场 / 进行中 / 已完成 / 违约。卡片按状态变色显示对应动作：待入场给 `取消` + `查看凭证`；进行中显示已停放时长与闸机计费金额；违约显示信用分扣减与累计次数。

### 5.7 车场端看板

车场名 + 日期 → 三统计块（今日预约 / 履约率 / 今日收入）→ 可预约额度条（总车位 / 可预约 / 已锁定 / 剩余，带调整入口）→ 未来 2 小时空闲预测 → **平台代收待结算卡**（待结算金额 + 本月累计 + 结算说明）→ 待核销列表。

## 6. 状态与异常

| 场景 | 处理 |
|---|---|
| 定位被拒 / 失败 | 不阻塞首页；提示去设置授权，保留手动搜索目的地 |
| 搜索无结果 | 空态 + 放宽建议（增大半径、切换排序） |
| 加载中 | 列表骨架屏，不用整屏 loading |
| 接口超时 | 统一 3 秒超时，指数退避重试 1 次，失败 toast + 重试入口 |
| **预测服务降级（BR-05）** | 界面**显著标注**橙色提示条：「预测服务暂不可用，已按实时余位 + 历史同期推荐」 |
| 余位 / 价格字段缺失 | 显示 `--`，不显示 0；同时上报日志 |
| 数据为估算值 | 卡片与详情页标注数据来源（腾讯地图 POI / 估算） |
| 支付失败 | 回滚锁位，toast 提示并允许重试 |
| 无满足约束车场 | 提示放宽条件（扩大半径、改到达时间、取消筛选） |
| 超时未入场 | 订单转「已违约」，凭证页倒计时替换为违约说明 |

## 7. 数据与接口契约

### 7.1 类型

```ts
type GeoPoint = { lat: number; lng: number };

type DataSource = 'poi' | 'rule' | 'estimated';

type ParkingLot = {
  id: string;
  name: string;                    // 腾讯地图 POI 标题
  address: string;
  location: GeoPoint;
  distanceM: number;               // 路径规划
  walkMinutes: number;
  pricing: {
    firstHour: number;             // 首小时标准价 —— 预支停车费的单价基准
    perHourAfter: number;          // 后续阶梯
    stepMinutes: 15 | 30 | 60;
    capPerDay: number;
    nightRate?: number;
    source: DataSource;
  };
  availability: {
    freeSpots: number;
    totalSpots: number;
    source: DataSource;            // 估算
  };
  reservableQuota: number;         // 车场开放的可预约车位数
  rating: number;
  tags: string[];
};

type Recommendation = {
  lot: ParkingLot;
  score: number;                   // 0–100
  factors: { fee: number; distance: number; availability: number; infra: number; reputation: number };
  reasons: string[];               // 可解释推荐理由，直接渲染为标签
};

type ReservationStatus =
  | 'pending_entry' | 'entered' | 'completed' | 'cancelled' | 'violated' | 'released';

type Reservation = {
  id: string;
  orderNo: string;                 // PR + yyyyMMdd + 6 位序列
  lotId: string;
  lotName: string;
  plateNo: string;
  arriveTime: string;              // ISO
  enterDeadline: string;           // arriveTime + 15min
  prepaidParkingFee: number;       // ceil(预留小时) × lot.pricing.firstHour
  serviceFee: number;              // 2
  totalAmount: number;
  status: ReservationStatus;
  qrPayload: string;
};
```

### 7.2 推荐评分

沿用 PM 表 5 的五因子体系。各因子归一化到 `0–1` 后加权求和，`× 100` 取整即为界面展示的综合评分：

| 因子 | 口径 | 默认权重 |
|---|---|---|
| 费用 | 预约时段试算总费用的归一化倒数 | 0.30 |
| 距离 | 步行距离 / 时间归一化 | 0.15 |
| 可用性 | 预约时段**预测**空闲率，低于 85% 警戒线降权或剔除 | 0.25 |
| 基础设施 | 按用户车型动态调整（纯电车看充电桩） | 0.20 |
| 口碑 | 车场评分与历史履约率 | 0.10 |

场景化权重切换（PM 2.2）：就医场景可用性权重上调至 0.35、费用降至 0.20；通勤场景费用上调至 0.40。

**约束过滤先行**：营业时间、车型大小、充电位、饱和红线、信用黑名单不满足者不进候选集。

`Recommendation.reasons` 由得分最高的因子生成文案（如「比周边省 ¥4」来自费用因子、「空位充足」来自可用性因子），直接渲染为卡片上的标签。

### 验证结论：Skyline 下地图浮层（2026-09-11）

`pages/spike-map` 验证页（commit `53addb0` / `7488c2e`）在微信开发者工具中实测，四项全部通过：

| 面板上的卡片能否收到点击 | ✅ 能 |

**结论**：D7 的「地图铺满 + 底部可上拖面板」可原样实现，无需退回「固定上下分栏」，也无需把首页单独切回 WebView 渲染。

验证中修掉的一个坑：面板收起态最初写成 `min-height: 60vh` + 硬编码 `translateY(420px)`，在 iPhone 8（667px 高）上面板顶部算出来是 687px，**整块跑到屏幕外，拖拽把手摸不到**——而这种现象与「手势被地图吃掉」无法区分，会导致错误的架构降级。改为按 `wx.getWindowInfo().windowHeight` 算出面板高度、收起时恒定露出 96px 把手后解决。
